# v2.1.0 実装計画書

## 1. 目的

`docs/v2.1.0/仕様書.md` に基づき、`popup.html` の新規追加フォームでアイコン入力を省略し、保存時にデフォルト絵文字 `🔖` を明示保存する変更を、最小影響で実装する。

## 2. 実装対象

- `popup.html`
  - 新規追加フォームと編集フォームで共用するアイコン入力欄の表示制御に必要な識別子を追加
- `popup.js`
  - 新規/編集モードに応じたアイコン入力欄の表示切替制御
  - 新規登録処理でアイコン値を `🔖` に固定して保存

## 3. 実装方針

1. UI変更は `popup.html` の新規追加フォームに限定する。
2. 保存ロジックは `popup.js` の新規作成処理のみ変更し、編集処理は変更しない。
3. 既存データを変更する処理（マイグレーション）は追加しない。

## 4. 作業ステップ

### Step 1: 事前確認

- `popup.html` の新規追加フォーム内でアイコン入力要素を特定する。
- `popup.js` の新規登録時の保存ペイロード構築箇所を特定する。

### Step 2: UI修正（`popup.html` / `popup.js`）

- `popup.html` のアイコン入力欄グループに識別用ID（例: `id="iconFormGroup"`）を設定する。
- `popup.js` の新規追加表示処理で、アイコン入力欄グループを非表示にする。
- `popup.js` の編集表示処理で、アイコン入力欄グループを表示する。
- 補助文言は追加しない。

### Step 3: 保存処理修正（`popup.js`）

- フォーム送信時、新規登録モード（`!editingJumpmark`）では保存データに `icon: "🔖"`（既存キー名に合わせる）を必ず設定する。
- フォーム送信時、編集モード（`editingJumpmark`）では入力されたアイコン値を保存する。

### Step 4: 影響範囲確認

- 編集画面のアイコン変更機能に影響がないことをコード上で確認する。
- `options.html` / `options.js` 側の追加UIには変更を加えないことを確認する。

### Step 5: 手動確認

回答方針に従い、自動テスト追加は行わず手動確認のみ実施する。

1. `popup.html` の新規追加フォームにアイコン入力欄が表示されないこと。
2. 新規登録した Jumpmark の保存データに `🔖` が入ること。
3. 既存のアイコン未設定 Jumpmark が変化しないこと。
4. 編集画面で従来どおりアイコン変更できること（新規追加後に編集画面へ遷移してもアイコン入力欄が表示されること）。

## 5. ロールバック方針

- 問題発生時は `popup.html` と `popup.js` の変更のみを切り戻せばよい。
- データマイグレーションを行わないため、データ復旧手順は不要。
